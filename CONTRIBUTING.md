# Contributing

Contributions should preserve the benchmark contract: fixed task splits,
training profiles, model seeds, checkpoint-selection rule, and hardware target
defined in [`configs/benchmark.json`](configs/benchmark.json). Do not modify a
published result in place without regenerating every dependent public artifact.

## Before opening a pull request

1. Create the lightweight artifact environment described in
   [`README.md`](README.md#reproduce-tables-and-plots).
2. Regenerate affected public outputs. For a change that affects either compact
   record, run `make reproduce PROFILE=<profile>` for each affected profile.
3. Verify both committed profiles with `make check-all`.
4. Include the source record, generated CSV tables, and generated PNG plots in
   the same change when a benchmark result changes.

The GitHub Actions workflow performs the final compile and artifact-integrity
check on every pull request and push to `main`.

## Adding a benchmarked model

1. Add its stable public name, fixed hyperparameters, supported tasks,
   architectures, seeds, and hardware implementation to
   [`configs/benchmark.json`](configs/benchmark.json).
2. Register an implementation or backend adapter used by
   [`scripts/run_benchmark.py`](scripts/run_benchmark.py). The model must use
   the fixed splits and training-only scaler supplied by `benchmark.py`.
3. Train every declared task, architecture, and seed for each intended profile.
   Neural models must use the profile's exact epoch budget and select the
   lowest-validation-loss checkpoint. Do not use test metrics for selection.
4. Synthesize each selected checkpoint with
   [`scripts/run_synthesis.py`](scripts/run_synthesis.py), using the declared
   VU13P, 5 ns, parallel-I/O, reuse-factor-1 protocol. Record unavailable
   synthesis explicitly; do not replace missing values with zero.
5. Collect raw outputs into the profile record with
   `python scripts/collect_benchmark_records.py --profile <profile>`, then
   regenerate and verify the public outputs.

For a proposed experimental method that does not yet cover the full declared
matrix, keep its results out of the published compact records until its scope
and missing entries can be stated clearly.

## Artifact rules

- `data/<profile>/benchmark_records.json` is the source of truth for public
  tables and plots. Edit it only through the collection workflow unless
  correcting an auditable data-entry error.
- Commit only the public tables in `results/<profile>/` and the training and
  Pareto PNGs in `plots/<profile>/`. Raw metrics, logs, caches, and generated
  HLS project trees remain ignored.
- Preserve the `20-epochs` and `200-epochs` profiles independently. Do not mix
  checkpoints, histories, or synthesis estimates between them except for the
  documented byte-identical BDT reuse.
- Keep result units and missing values faithful to the synthesis report.
  Latency is reported in ns; LUT, FF, DSP, and BRAM18 values are HLS estimates;
  error bars and `*_std` columns are sample standard deviations over available
  seeds.
- Keep plot names and table names generated by
  `scripts/generate_benchmark_artifacts.py`. Do not hand-edit generated files.

## Scope and review

Keep pull requests narrowly scoped and explain changes to the benchmark
protocol, dependency versions, result values, or public artifact schema. Full
retraining and HLS C-synthesis require their backend-specific environments;
Vitis HLS additionally requires a valid license. The lightweight reproduction
environment is sufficient to regenerate and verify all committed tables and
plots.
